# 平台登录与发布可靠性修复设计

## 背景

Agent 使用 `opub` 0.6.4 发布时，小红书、快手、B站、视频号和百家号在登录阶段失败，微博在上传文件阶段失败。诊断确认这些失败并非同一个账号问题：小红书和快手保存的登录态稍后可以正常复用；B站交互式登录与 Agent 重定向日志冲突；视频号和百家号存在登录完成判断缺口；微博依赖不稳定的文件选择事件。此外，小红书模块在 Python 3.9–3.11 下存在语法错误。

## 目标

- 不新增 CLI 或技能参数。
- Agent 仍只向用户反馈环境状态、发布开始和发布结果，不展示过程日志。
- 浏览器平台完成登录后能够稳定保存并复用登录态。
- B站首次登录在非交互 Agent 环境中仍能提供可操作的独立登录窗口。
- 微博上传不再依赖按钮必须触发文件选择事件。
- 恢复小红书对项目声明的 Python 3.9–3.11 兼容性。

## 非目标

- 不重构全部平台的统一登录状态机。
- 不改变账号文件格式、默认路径或错误码体系。
- 不改变普通终端用户已有的交互式 B站登录行为。
- 不在本次修复中调整平台发布表单的其他选择器。

## 设计

### 小红书与快手

扫码登录成功后，使用当前已经登录的页面确认登录完成并保存 `storage_state`，不在原浏览器仍打开时启动第二个浏览器立即复验。登录函数返回后原上下文会关闭；后续正式发布流程仍会加载账号文件并执行既有登录校验，因此不会降低发布前的账号有效性检查。

### 视频号

登录完成判断采用两层证据：发布控件可见时立即成功；否则，当 URL 已进入发布页或管理页且登录二维码、登录 iframe 均不可见时也判定成功。登录页、二维码仍存在或 URL 未进入认证后页面时继续等待。

### 百家号

为 `BaiJiaHaoVideo` 覆盖 `is_login_completed`，复用现有 `_is_baijiahao_auth_page_valid` DOM 判断。这样即使百家号使用单页应用、登录后 URL 没有按预期变化，只要发布页面结构已经出现即可保存登录态。

### 微博

进入上传页后优先查找已有的 `input[type=file]` 并直接调用 `set_input_files`。仅当文件输入框尚未创建时，才点击上传按钮并等待 `filechooser` 事件。登录重定向仍映射为原有的安全登录过期结果。

### B站

`run_biliup_command(..., interactive=True)` 保留真实终端中的继承式交互。检测到当前标准输入或输出不是终端时，在 Windows 上为 `biliup login` 创建独立控制台并同步等待退出；该窗口承载二维码和登录交互，Agent 的重定向日志不接收这些过程输出。其他系统继续使用当前交互方式，避免引入未验证的平台专用终端实现。

独立窗口退出后仍以 `biliup` 返回码和账号文件是否存在作为成功条件，不增加参数或新的用户步骤。

### Python 兼容性

把小红书 f-string 表达式中的反斜杠替换操作提前计算，确保 Python 3.9–3.11 可以解析模块，输出内容保持不变。

## 错误处理

- 登录未完成继续返回 `AUTH-001`，不改变对外契约。
- 微博无法找到文件输入框且按钮也未触发文件选择时，继续返回 `PUB-weibo`，但保留底层简短原因供 Agent 内部诊断。
- B站独立登录窗口启动失败或返回非零时继续返回 `AUTH-001`。
- 过程异常只进入内部日志，不扩大 Agent 用户可见反馈范围。

## 测试

采用测试先行：

1. 小红书、快手登录保存后不调用即时二次 `cookie_auth`，并返回成功。
2. 视频号在认证后 URL 且登录控件消失时判定成功，在二维码仍可见时保持未完成。
3. 百家号登录完成判断委托现有 DOM 校验。
4. 微博已有文件输入框时直接上传，不等待 `filechooser`；没有输入框时保留按钮后备路径。
5. B站非终端 Windows 环境使用独立控制台，真实终端维持当前行为。
6. Python 3.11 可以编译并导入小红书模块。
7. 运行相关平台测试、完整测试套件及包构建检查；既有且与本次无关的失败单独报告，不伪装为通过。

## 验收标准

- 六个报告中的失败点都有对应自动化回归测试。
- 不新增公开 CLI 参数或技能参数。
- Agent 用户反馈契约保持不变。
- 账号文件路径与格式保持不变。
- 修复代码可在 Python 3.11 编译。
