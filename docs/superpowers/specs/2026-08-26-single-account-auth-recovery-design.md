# 单账号与登录恢复设计

## 背景

2026-08-26 的七平台真实发布执行了 8 次账号级发布。抖音、B站、百家号和第二个微博账号成功；小红书账号被平台限制；快手扫码超时；视频号和第一个微博账号实际已跳转到登录页，却分别被误报为文件控件或上传按钮超时。

用户确认微博以后只保留一个账号：保留本次发布成功的第二个微博账号，失效的第一个账号归档且可恢复。小红书不重试；实现完成后只重试快手和视频号。

## 目标

- 所有平台在统一发布流程中只使用一个自动发现的账号文件。
- 微博不再循环多个账号，也不再产生 `weibo_1`、`weibo_2` 结果键。
- 视频号和微博在选择素材前识别登录失效，并返回结构化的 `login_expired` 账号异常。
- 编排器只在确认素材尚未提交时自动重新登录并重试一次。
- 登录恢复失败时保留明确的 `AUTH-001` 结果，不用控件超时掩盖账号问题。
- 不重复发布已经成功的平台或微博账号。

## 非目标

- 不解除或绕过小红书平台的账号限制。
- 不新增 `--account-file`、账号序号或其他账号选择参数。
- 不支持同一平台多账号发布。
- 不修改标题、描述、标签、发布时间或素材生成逻辑。
- 不自动重试素材已经交给平台后的未知失败。

## 方案选择

采用“单账号规范化 + 编排器一次性登录恢复”。

未采用的方案：

- 在视频号和微博上传器中分别实现完整的重新登录与重试，会复制编排逻辑。
- 只整理 Cookie 而不修改运行时识别，未来仍会把失效登录误报为页面控件超时。
- 临时移走账号文件完成一次发布，无法形成稳定的单账号契约。

## 账号存储与迁移

每个平台的规范账号文件是其上传器子目录内的 `account.json`。微博规范路径为：

```text
cookies/weibo_uploader/account.json
```

迁移步骤：

1. 建立 `cookies/weibo_uploader/archive/`。
2. 将失效的第一个微博账号文件移动到 `archive/`，保留原文件名并附加迁移时间，确保可恢复。
3. 将本次发布成功的第二个微博账号文件移动为规范的 `account.json`。
4. 迁移后只让账号发现逻辑检查规范文件；`archive/` 不参与发现。

迁移前先根据真实登录诊断确认两个文件的身份：成功账号必须能进入 `https://weibo.com/upload/channel` 并看到上传按钮；失效账号必须落到 `newlogin`。如果诊断与本次记录不一致，停止迁移并报告，不根据文件名猜测账号身份。

## 账号发现

`publish.config._discover_account_files()` 对每个平台返回至多一个账号路径：

- 优先使用上传器子目录的 `account.json`。
- 为兼容历史安装，当规范文件不存在且只发现一个旧 JSON 文件时，使用该文件。
- 当规范文件不存在且发现多个旧 JSON 文件时，不选择任意一个；该平台视为未配置账号，由登录流程写入规范 `account.json`。
- 返回值保持现有 `<platform>_account: <path>` 结构，但值不再是逗号分隔列表。

## 发布编排

`publish.orchestrator.publish_one_item()` 对每个平台只选择一个账号，并执行以下流程：

1. 读取单个账号路径；不存在时使用 `default_account_file(platform)` 的规范路径。
2. 调用现有登录校验。
3. 调用平台发布器。
4. 若结果不是 `login_expired`，直接记录结果。
5. 若结果是发布前 `login_expired`，通过 `ensure_account_login(platform, account_file, force=True)` 跳过 Cookie 检查并调用平台 `setup(..., handle=True)` 强制重新登录。
6. 登录成功后对同一平台重试一次；无论成功或失败都不再进行第二次恢复。

每个平台发布最多执行两次：首次尝试和一次确认安全的登录恢复重试。结果键始终是平台标识，例如 `weibo`，不再带账号序号。进度输出也删除“账号 1/2”形式。

## 登录失效识别

平台发布结果使用现有字典结构，并在登录失效时增加：

```python
{
    "success": False,
    "message": "cookie 已失效，请重新扫码登录",
    "account_issue": True,
    "issue_type": "login_expired",
    "safe_to_retry": True,
}
```

`safe_to_retry=True` 只能在选择视频或图片之前设置。

### 视频号

打开发布页后等待以下状态之一：

- 发布页出现 `input[type="file"]`：继续上传。
- URL 跳转到 `login.html`：返回 `login_expired`。
- 页面出现 `qrconnect` 登录 iframe：返回 `login_expired`。
- 等待期结束且没有登录标记：保留页面加载错误，不把它标成可安全重试的登录异常。

视频号继续避免在单独浏览器上下文中反复做 Cookie 预检；真实登录状态由上传会话判断。

### 微博

Cookie 校验和正式上传都等待明确状态：

- 上传页出现 `WEIBO_UPLOAD_BUTTON_SELECTOR`：登录有效。
- URL 包含 `newlogin`、`passport.weibo.com`、`login.sina.com`、`/login` 或 `/sso/`：登录失效。
- 页面出现可见登录标记：登录失效。
- 等待期结束：返回页面加载错误。

这样可以覆盖本次观察到的 `newlogin?...retcode=6102`，并避免固定等待 3 秒后过早判断。

## 错误处理与重复发布保护

- 自动恢复最多一次，并由编排器记录是否已经恢复过。
- 只有 `account_issue=True`、`issue_type="login_expired"`、`safe_to_retry=True` 同时满足时才允许自动重试。
- 上传器一旦调用 `set_input_files()` 或接受 file chooser，不再返回 `safe_to_retry=True`。
- 扫码超时返回 `AUTH-001`，不继续调用发布器。
- 平台限制、上传失败、发布结果未知等错误不触发自动恢复。
- 已成功的抖音、B站、百家号、微博不包含在后续真实重试命令中。

## 测试设计

所有行为按 TDD 实现，先观察测试因缺少新行为而失败。

### 单账号发现

- 规范 `account.json` 存在时只返回该文件。
- 只有一个旧文件时兼容该文件。
- 多个旧文件且无规范文件时不任意选择。
- 微博结果值不包含逗号分隔账号列表。

### 单账号编排

- 每个平台只调用一次登录校验和一次发布。
- 微博只产生 `weibo` 结果键。
- 输出不包含账号序号。

### 登录状态识别

- 视频号重定向到 `login.html` 时返回可安全重试的 `login_expired`。
- 视频号出现登录 iframe 时返回可安全重试的 `login_expired`。
- 微博进入 `newlogin?...retcode=6102` 时判定 Cookie 无效。
- 微博出现上传按钮时判定 Cookie 有效。
- 普通页面加载超时不标记为可安全重试。

### 一次性恢复

- 首次发布返回可安全重试的 `login_expired` 时调用强制登录并只重试一次。
- 强制登录失败时不重试发布并返回账号错误。
- 第二次发布失败时不再触发第三次发布。
- 非登录错误和 `safe_to_retry=False` 不触发重新登录。

### 回归验证

- 运行账号发现、编排、视频号、微博相关测试。
- 运行完整 `unittest` 套件；已知百家号超时测试需要单独处理其装饰器重试问题，不用无限等待冒充通过。
- 运行 `opub --help`，确认没有新增账号选择参数。

## 验收标准

- 微博磁盘上只有一个可发现账号，失效账号仍可从 `archive/` 恢复。
- `opub` 对微博只发布一次并只输出 `weibo` 结果。
- 视频号和微博登录失效时不再显示文件控件或上传按钮超时。
- 登录失效只触发一次扫码恢复和一次发布重试。
- 自动恢复不能在素材已提交后触发。
- 相关测试和除已知百家号挂起测试外的现有回归测试通过。
- 快手与视频号真实重试完成，其他成功平台没有重复内容。
