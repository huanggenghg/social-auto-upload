# Agent 发布反馈精简设计

## 目标

`opub-cli` 技能只面向 Agent。Agent 执行发布时，不向使用 Agent 的用户展示或转述 `opub`、上传器、依赖安装和浏览器自动化产生的过程日志，只反馈发布环境状态、发布开始和发布结果。

## 范围

- 只修改 `skills/opub-cli/SKILL.md` 及其契约测试。
- 不修改 `opub` CLI，不增加命令行参数，也不改变直接执行 `opub` 时的输出。
- 发布前收集并确认素材、标题、描述、标签和平台的现有要求保持不变。
- 发布过程中浏览器自行展示登录或扫码交互，Agent 不再追加提醒。

## Agent 反馈契约

Agent 对用户只发送以下三类状态：

1. **发布环境状态**：开始检查、环境已就绪，或环境异常的简短结论。
2. **发布开始**：确认发布已经启动，可包含目标平台和素材数量。
3. **发布结果**：各平台成功或失败、稳定错误码、结果链接和总体计数。

Agent 不发送上传进度、依赖安装细节、登录过程、浏览器操作、调试输出、异常堆栈或原始 stdout/stderr。环境或发布失败时，只提取用户可执行的结果和错误码，不粘贴原始日志。

## 执行与日志处理

Agent 仍使用现有的 `opub ...` 命令。执行时必须将 stdout 和 stderr 重定向到 Agent 内部的临时日志，禁止把命令原始输出流直接展示给用户。Agent 可在内部读取该日志，以判断退出码、提取错误码、平台结果和链接；内部读取不得转化为过程消息。

发布运行期间不发送轮询进度。浏览器交互不改变，Agent 等待命令完成后再输出最终发布结果。

## 错误处理

- 环境失败：反馈“发布环境异常”以及对应 `ENV-xxx` 和简短建议。
- 配置失败：在最终结果中反馈 `CFG-xxx`，不附原始日志。
- 登录失败：在最终结果中反馈 `AUTH-xxx`；发布过程中不追加扫码提示。
- 平台失败：在最终结果中反馈 `PUB-<platform>` 和简短原因。
- 意外失败：反馈 `RUN-xxx` 和简短结论，不展示堆栈。

## 测试

在现有技能黑盒测试中增加契约断言：

- 技能明确要求重定向并隐藏 stdout/stderr。
- 技能明确禁止向用户展示过程日志和发布进度。
- 技能明确限定三类用户反馈。
- 技能明确要求保留最终错误码、平台结果和结果链接。
- 技能不得要求新增 Agent 专用 CLI 参数。
